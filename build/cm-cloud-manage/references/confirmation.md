# 确认与组合任务

首次写计划或组合任务时读取。本文件是确认卡与确认编排的唯一公共定义；领域文档仅追加业务影响。

## 业务确认

记忆备份场景的目录范围按 [记忆备份与恢复](memory.md) 执行：固定为个人云的 `AI空间/记忆库`，并允许计划创建缺少的父级目录。此场景不使用下文普通业务的专属目录落点限制或默认目标；确认卡展示固定记忆库下的实际批次、类型目录，以及计划创建的父级目录。其余计划、确认与执行契约不变，不能绕过 CLI 或服务端权限。

云端WRITE保持计划确认。云端写操作的落点只能是智能体专属目录及其子目录：用户未说明落点时默认专属目录，卡面目标按专属目录展示并写出其实际路径；用户要求写到专属目录外时不生成计划、不执行，先提示「只能操作 <专属目录实际路径> 内的文件」。读取、相册、分享创建与订阅不落云盘路径，不受此限；转存受此限。普通本地下载（conflictPolicy=fail/rename，默认fail）由CLI校验后直接执行，不再要求二次确认；conflictPolicy=overwrite仍返回确认计划。不可为减少询问而自行确认覆盖计划。用户后续明确同意已经展示且唯一的计划或计划组时，再执行确认；含糊回答、多个未绑定计划、对象或影响改变都不能沿用确认。对话确认是流程约束，不是用户身份认证。部署关闭对话确认时使用已支持的宿主签名事件或人工TTY，不修改开关。

## 确认卡

```text
【待确认】<动作>（<数量>）
· 对象：<真实名称；源 → 目标>
· 选项：<有效默认值或用户指定值；没有则省略>
· 影响：<新增、公开、覆盖、解绑等实际影响>
回复“确认”后执行；也可以告诉我要调整的地方。
```

每项独立成行，可用代码块或列表。对象有歧义先消歧。数量未知不填0，不展示内部引用、令牌和与决策无关的实现细节。计划不能描述为“已完成”。写操作的目标默认展示为智能体专属目录并写出其实际路径；目标越出专属目录时不生成计划。公开分享注明范围和有效期，订阅注明不会自动转存；领域追加项见对应文档。

## 多动作确认

同一请求里的多个云端写动作使用CLI `orchestrate`，冻结为一个operationRef和planHash，展示一张卡，一次确认、一次执行。不要由Agent拼装多个独立计划冒充一个冻结计划。单动作仍用领域命令。

先通过 `<技能根>/scripts/cm_cloud_cli_api.py help --topic orchestrate --format json` 读取帮助和对应schema。`orchestrate --step "<domain> <action> ..." --step "..." --format json` 中每个step是一整个参数；空格值用单引号包住，JSON数组保留双引号。只接入云端写命令，读请求、下载、auth单独执行。

依赖前序产物使用 `?step1.folderRef` 等明确绑定；只引用此前步骤返回且唯一的引用。新建目录后上传可在同一编排内完成，卡面写明新目录名称、上传文件、同名策略以及“目标来自步骤1”。已有原生复合操作（如album create携带fileRefs）仍优先直接使用。

转存多张图片后建册或加图，使用显式数组绑定 `--fileRefs '["?step1.fileRefs"]'`，表示把第1步的成功文件集合整体传入。仅支持文件转存（S20/S21）到建册加图或相簿加图（S30/S31）；该数组只能包含这一个占位符，不混入其他引用，不接受目录产物。CLI核验数量、真实文件及图片类型后继续，失败/部分成功/未知均停止链路。旧 `?step1.resultRef` 仍要求唯一，不能用于承接多文件，也不能自动选第一张或重新出卡掩盖失败。确认卡应写明图片数量、范围及“图片来自步骤1”。

任一步失败、未知、拒绝、需授权或过期时停止后续步骤，保留已完成结果，不重做成功项。编排状态查询只读台账，不能把查状态当作自动继续执行。

### 组合确认卡模板

【待确认】<任务概括>（共N步）
1. <动作、对象、目标>
2. <动作、对象；依赖目标写“步骤1新建的目录”等>
选项：<适用的同名处理、范围、有效期>。
影响：<真实新增/公开等影响>。
回复“确认”后，我会按顺序执行以上步骤。

仅使用同一个CLI冻结计划中已有的步骤；缺失可选行省略，不展示命令、占位符或内部引用。对用户的选择提示不改变CLI的确认要求。结果统一使用[output.md的T4](output.md)。

## 普通业务执行协议

以下 `operation` 命令均使用 `<Python> "<技能根>/scripts/cm_cloud_operation_api.py" <confirm|execute|status> ... --format json`；脚本后不再加 `operation`，不得使用 `cm_cloud_cli_api.py` 执行。完整示例见[调用入口与参数](protocol.md#调用入口与参数)。

1. 保存原计划引用、摘要和profile，在对话内关联用户确认的业务影响。
2. 使用operation confirm --operation-ref <ref> --plan-hash <hash> --confirmation CONFIRM --profile <profile>。
3. 确认成功后把回执data.confirmToken交给operation execute --operation-ref <ref> --confirm-token <token> --profile <profile>。缺令牌不执行，不重发原写命令。
4. 令牌只对该计划一次有效，不能展示、跨计划复用或重放。过期计划重新发起，不循环confirm。结果未知先查已有任务，不能重新提交写请求。

## 授权退出例外

明确重新授权使用 `auth reauthorize`：一张确认卡说明将发起新授权，取得入口后停用旧票据，完成前无法正常使用；确认后用同命令携带 `--operationRef` 和 `--planHash` 执行。计划记录台账防重放，不使用 `operation confirm/execute/status`。CLI仅强制请求一次，不解绑或完整退出；新会话确认后清除外层旧票据并保存待完成标记。失败或未知不重复强制请求。用户完成后可直接继续原业务，由普通取票先承接新授权；只有单纯问状态才用普通auth login。取得入口不等于完成授权，取票失败不退回旧票据。

auth revoke/logout返回op_引用，不进普通operation台账；分别用原命令携带--operationRef和--planHash执行，不能使用operation confirm。远端解绑与本地清理各自需要自己的计划字段，不复用。完整退出只展示一次业务影响，按已确认范围顺序执行两段；即使远端失败/未知，也继续已授权的本地清理，除非用户取消整个动作。详见[授权](auth.md)。
