# files 文件管理

> 领域说明：仅在 `SKILL.md` 已把动作路由到 `files` 后加载。执行前先取 `cmcloud help --topic files --format json` 与 `cmcloud schema --command-id <command-id> --format json`。**参数类型、必填、枚举全集、上限与成功判定一律以 CLI schema 为准**；本文件只给命令索引、参数名索引和编排规则，不内联 schema、下游字段名或成功码。

## 何时触发

自身记忆的备份与恢复先读 [记忆备份与恢复](memory.md)：该场景仅在个人云根目录下的 `AI空间/记忆库` 内读写云端记忆，允许按已授权备份任务计划创建所需目录、按恢复任务选取本地暂存目录。下文关于普通文件的全个人云读取、专属目录写入限制、默认专属根落点、缺目录先追问及下载目录由用户指定的规则不覆盖这些场景特例；其余 CLI 参数、确认、状态与完整性规则仍适用。

> 以下为**触发线索**；单独的词只有在云盘语境下、且能绑定明确对象时才成立（对象来自当前附件、用户指代或上一轮 CLI 回执；不唯一先消歧）。

- **上传 `cmcloud files upload`**：上传、传到云盘、把…放到云盘、存到…文件夹、导入云盘（宾语＝本地文件/附件）。
- **搜索 `cmcloud files search`**：找、搜索、查找、不记得放哪、有没有、文件在哪里、找回（＋名称/类型/关键词）。
- **列目录 `cmcloud files list`**：文件夹里有什么、列出文件夹当前层、云盘根目录（宾语＝目录/文件夹）。个人云根用 `rootScope=personal`。
- **取得专属根上下文 `cmcloud agent info`**：写操作需要专属目录作为落点（含用户未说明落点时的默认落点），或用户明确以专属根作为目标，或平台拒绝原目标后用户选择改到专属目录。
- **文件详情 `cmcloud files info`**：多大、文件信息、详情、路径、在哪个目录、在哪儿（宾语＝某个文件）。
- **新建目录 `cmcloud files mkdir`**：新建文件夹、创建文件夹、建个目录（宾语＝父目录 + 名称）。
- **下载 `cmcloud files download`**：下载、保存到本地、保存到 D 盘、导出到电脑（宾语＝文件 + 本地目录）。
- **复制 `cmcloud files copy`**：复制、备份、拷贝、归档到文件夹（宾语＝源 + 目标目录）。

## 何时不触发

- `上传了什么`/`上传记录` → `cmcloud activity list --eventKinds upload`
- `转存了什么` → 转存动态；`保存这个外链` → `cmcloud share save`
- `看过什么` → `cmcloud activity list --eventKinds browse`；`我发出的分享` → 参见 [分享查询范围](share.md)，不能把 `listKind=sent` 当成全部已发公开分享
- `外链里有什么` → `cmcloud share browse`
- 整理/成册意图：`整理这些照片`、`分类图片`、`归档照片`、`按月归档照片` → 本期不支持，不调用
- 读取覆盖当前授权账号的整个个人云：搜索、列目录、详情、下载可作用于任意位置。写操作（上传、新建目录、复制、转存）的落点只能是智能体专属目录及其子目录；用户未说明落点时默认专属目录，用户要求写到专属目录外时不生成计划、不执行，先提示「只能操作 <专属目录实际路径> 内的文件」并写出该目录的实际路径；**改写目标须重新向用户确认**。相册、分享创建与订阅不落云盘路径，不受此限；转存仍须落在专属目录内。
- 云端文件删除、移动、改名及描述修改 → 本期不支持，不调用。上传同名自动改名、相簿及故事改名不属于此限制。
- 不提供独立批量路径查询；普通文件搜索、详情和回执中已有路径展示保持不变。

## 用户话术到结构化参数

> 本节说明各场景下**每个参数怎么选**；**参数类型、必填、上限、默认值与枚举全集以 `cmcloud schema` 为准**。
> 本领域命令：`cmcloud files upload`、`cmcloud files search`、`cmcloud files list`、`cmcloud files info`、`cmcloud files mkdir`、`cmcloud files download`、`cmcloud files copy`（无路由枚举）；参数与枚举由 `cmcloud help --topic files`、`cmcloud schema --command-id <command-id>` 下发。

**上传 `cmcloud files upload`**

- `localFile`：当前附件，或用户明确指定的本地文件（**必填**；"上传这个""把桌面的 a.docx 传上去"）；必须存在且可读（大小、摘要由 CLI 计算）。
- `destinationRef`：宾语＝用户说出的云盘目录（**必填**；"传到 /AI空间/…/周报"）；必须已存在，引用来自当前账号的可信 CLI 回执。**落点只能是智能体专属目录及其子目录**：用户未说明落点时默认专属目录，使用 `agent info` 回执的 `dedicatedRoot.rootRef`；指定的目录不存在时先追问，不自动新建；用户指定专属目录外的位置时不生成计划，先提示「只能操作 <专属目录实际路径> 内的文件」。
- `overwritePolicy`：用户未明确时**默认 `rename`**（同名时由服务端改名保留，不覆盖原文件）；其他两个可选参数："同名就报错"＝`reject`，"自动换个名字"＝`dedupe`；**不接受覆盖原文件语义**。`rename`/`dedupe` 下改名是**预期结果**：CLI 以**实际名**返回（`data.name`）并给出 `data.renamed=true`、`data.renamedFrom=<本地文件名>`，**不得当成失败或契约不一致**。
- `dedupe` 返回已有文件且未建立上传会话时，CLI 核对详情中的目标目录、大小和同算法内容摘要；核验一致才复用，回执为 `data.reused=true`、`counts.uploaded=0`、`counts.reused=1`，应反馈“已核验并复用已有文件”，不能说成真实上传或新增副本。摘要缺失或不一致时返回 `CONFLICT`，可建议使用 `rename` 另存；不凭同名同大小宣告内容相同，不擅自更改冲突策略。

**搜索 `cmcloud files search`**

- `folderRef` / `folderRefs`：限定搜索目录，二选一；单目录用 `folderRef`，多目录用 `folderRefs`（1–20 个、不重复）。必须使用当前账号的真实目录引用，CLI 核验目录后转换为上游 `conditions.includeFileIdList`，可与关键词、类型、时间、大小组合；不传则搜索整个授权个人云。目录覆盖范围由上游接口决定，不把该参数解释为仅列直接子项，也不额外承诺递归深度。只限定目录也可以搜索；不得把目录名称字符串或本地路径当作目录引用。
- `keyword`：用户给出的**名称词**（文件名/后缀），可选；**仅按文件名包含匹配**。三类词要分开：① 名称词（“周报”“合同”“2024 预算”）→ 作 `keyword`；② 泛类型词（图片/视频/文档/压缩包…）→ **不作关键词**，只用 `typeList`；③ **内容词**（“猫”“海边”“红衣服”等描述画面或文件内容的词）→ **不作关键词，也不得降级成“按类型取全量”**：本能力无法识别画面或文件内容，应先如实说明这一点，再请用户给出文件名线索或时间/类型/相册等可收窄条件。至少提供关键词、类型、后缀、地址/标签、时间或大小范围之一；仅按类型、后缀或时间查找时不编造关键词，也**不得**在没有用户新线索时把内容检索改写成类型/全量检索。
- `contentType`：兼容的单类型入口；`typeList` 是标准多类型筛选，类型值为 `0`（其他）、`1`（图片）、`2`（音频）、`3`（视频）、`4`（文档）、`5`（APP）、`6`（压缩）、`100`（目录）。两者不能同时提交。
- `extension`：兼容的单后缀入口；`extensionList` 支持标准多后缀筛选。两者不能同时提交。
- `addressList`/`tagList`：图片的地理标签/标签筛选，最多各 10 项；`sizeRange` 以 byte 筛选文件大小。未传 `typeList` 时 CLI 自动限定为全部文件类型；同时包含文件类型和目录 `100` 时忽略目录并在回执中提示；仅包含 `100` 时直接说明文件夹不支持按大小筛选，不调用下游。`isMatchFolder=true` 时必须提供 `keyword`。
- `timeList`：标准多时间范围筛选，最多 10 项；与兼容的 `from`/`to`/`timeField` 不能混用。`takenAt` 只允许 `typeList=["1"]` 的图片搜索。
- `from`/`to`：时间词规范化为半开区间，"最近"默认 7 天；只给出一端时另一端由 CLI 补齐（纪元下限／当前时刻），不需要用户补全。
- `timeField`：取值 `createdAt`／`updatedAt`／`takenAt`；用户明确"拍摄时间" → `takenAt`、"修改时间" → `updatedAt`，否则用 schema 默认。
- `pageSize`/`cursor`：`pageSize` 默认 10、最大 1000（`fileIdList` 路径暂未公开）；`cursor` 在用户说"继续/下一页"时取上一轮回执的游标。SearchSkillFile 现网的 `pageAfter` 为字符串数组，CLI 原样保存并回传；同时兼容文档所述对象数组。上游可信返回 `total` 时会原样体现在回执 `page.total`。
  搜索无上游结束标记：本页不满或无游标即取尽、满页且有游标才未取尽；判定由 CLI 完成并体现在 `page.complete`（口径见 [协议](protocol.md)）。

**列目录 `cmcloud files list`**

- `rootScope`：省略或 `personal` 时列个人云根；用户明确要专属根时传 `dedicated`。
- `folderRef`：宾语＝当前目录或用户指代的目录；只能来自可信回执。用户只给出目录名称、当前上下文又没有其引用时，先用 `files search` 定位目录并取得 `folderRef`；唯一命中后再列目录，命中多个时先让用户选择。省略时按 `rootScope` 列根目录；回执的 `folderRef` 可用于后续操作，专属根查询还返回 `data.dedicatedRoot.rootRef/namePath`。不得从路径推测真实目录 ID。
- `files list` 始终只列当前目录的直接子项，不进入子文件夹。用户要求“所有文件”时先返回当前目录第一页；只有用户说“继续/下一页”时，才使用上一轮游标继续列当前目录。若还需查看某个子文件夹，应使用该子文件夹的 `folderRef` 单独查询。
- `sort`："最新的/按时间" → 按创建或修改时间倒序；"按大小/大的在前" → 按大小降序（取值见 schema）。
- `pageSize`/`cursor`：`pageSize` 默认 10，用户要"多给点/前 N 条"时指定；`cursor` 在用户说"继续/下一页"时取上一轮回执的游标。

**文件详情 `cmcloud files info`**

- `fileIds` 或 `dynamicRefs`：二选一；宾语来源为当前文件/用户指代（`fileIds`，已验证 ID）或动态结果引用（`dynamicRefs`，须映射已确认）。（数组写法见 [调用入口与参数](protocol.md#调用入口与参数)）
- `fields`：取值 `name`／`size`／`time`／`location`；"文件名/叫什么" → `name`；"多大/占多少空间" → `size`；"在哪/路径/哪个目录" → `location`；"什么时候传的" → `time`；未请求的字段不额外补查。

**新建目录 `cmcloud files mkdir`**

- `parentRef`：宾语＝用户指定的父目录（**必填**）；使用当前账号可信 CLI 回执中的目录引用，且**只能位于智能体专属目录及其子目录内**；用户指定专属目录外的位置时不生成计划，先提示「只能操作 <专属目录实际路径> 内的文件」。
- `name`：用户给出的目录名（**必填、非空**；≤255 字节，不含路径分隔符等非法字符）。
- 本命令**无同名策略入参**：同名由平台返回冲突，不提供复用/跳过，需由用户改名，或先 `cmcloud files list` 定位既有目录后改用其引用。

**下载 `cmcloud files download`**

- `resources`：宾语＝用户选定的文件；非空，可来自当前授权账号的个人云任意位置。（数组写法见 [调用入口与参数](protocol.md#调用入口与参数)）
- 批量 `resources` 逐项校验：单个引用未登记、已过期、跨 profile 或类型不符时，该项记为失败且绝不进入下游，其他有效引用继续下载；本地目标目录等请求级错误仍整单拒绝。
- `localDirectory`：用户指定的本地目录（**必填**）；必须是已存在的绝对目录；是否可写由宿主声明的允许范围决定，CLI 不额外限制目录。
- `conflictPolicy`：用户未明确时**默认 `fail`**（本地已存在同名文件即报错，不覆盖、也不改名）；"自动换个名字"＝`rename`；"覆盖/替换"＝`overwrite`，**只在用户当次明确要求覆盖时才传**（普通下载不弹确认卡，覆盖下载仍按确认计划执行）。
- `integrityPolicy`：用户不指定时用默认；"校验一下/确认完整"＝`sha256`，否则 `size`（取值见 schema）。

**复制 `cmcloud files copy`**

- `resources`：宾语＝用户选定的文件/目录；非空，**源可来自专属目录内或外**、云盘内任意当前用户可访问的位置。（数组写法见 [调用入口与参数](protocol.md#调用入口与参数)）
- 批量 `resources` 逐项校验：单个源引用未登记、已过期、跨 profile 或类型不符时，该项记为失败且绝不进入下游，其他有效源继续复制；`destinationRef` 无效、越权或计划校验失败仍整单拒绝。
- `destinationRef`：宾语＝用户指定的目标目录；使用当前账号可信 CLI 回执中的目录引用，且**只能位于智能体专属目录及其子目录内、不得在专属目录外**；用户指定专属目录外的目标时不生成计划，先提示「只能操作 <专属目录实际路径> 内的文件」。

files 各命令**无路由枚举**，按动作直接对应主命令。

## 读流程

`cmcloud files search`/`cmcloud files list`/`cmcloud files info` 直接执行。

- **搜索**：`cmcloud files search` 由 CLI 内部完成检索，Skill 不感知内部检索分支。**取尽判定由 CLI 完成并体现在 `page.complete`**：本页不满或无游标即取尽（`complete=true`），只有满页且仍有游标时才是 `complete=false`；`total=null` 不表示未查全。范围未核验时按 `complete=false` 说明；空结果不擅自扩大条件；CLI 报契约不匹配时按其错误处理，不猜测。
- **列表**：`cmcloud files list` 单次只查询当前目录的一页直接子项，不进入子文件夹；有后续页时返回游标，用户说“继续/下一页”后再取下一页。以 `page.complete` 判定当前目录是否取尽，未取尽时如实标注“未查全”。省略 `folderRef` 时默认列个人云根；专属根须传 `rootScope=dedicated`。切换 profile、重新授权或引用失效后须重取。
- **详情（`cmcloud files info`）**：按可信的真实文件 ID（`fileIds`）或动态引用（`dynamicRefs`）返回名称、大小、位置；字段不可得时如实标注，**不得用名称或目录文本推断路径或大小**。由 activity 域动态结果触发的补查，其"何时补查、映射是否成立"以 `activity.md` 为准，本文件只负责命令本身。
- 无权威总数时输出"已找到/已加载"；仅 `page.complete=false`（满页且有游标）时补"未查全"并允许继续翻页；`complete=true` 时不得再说"未查全/还有更多"。空结果明确提示，不擅自扩展范围。

## 写流程与确认点

**需要用户确认**（云端写）：`upload`、`mkdir`、`copy` —— 统一走计划 → 确认 → 执行。
**下载**：fail/rename直接执行；overwrite保留覆盖确认。
**写落点约束**：`upload`/`mkdir`/`copy` 的云端落点只能是智能体专属目录及其子目录（未说明时默认专属目录）；`copy` 的**源不受限**、可在专属目录内外。用户要求落到专属目录外时不生成计划、不执行，先提示「只能操作 <专属目录实际路径> 内的文件」。

> 以下为业务语义步骤；**Skill 只调用一次对应的 `cmcloud files <action>` 命令**，其余环节（申请上传、字节传输、上传完成校验、路径补查、任务轮询）都在 CLI 内部完成，不由 Skill 分步调用。

1. **上传**：确认本地文件及用户指定的目标 → CLI 内部完成申请、传输与上传完成校验 → 核验详情后报告名称/位置。秒传可跳过传输与完成校验，但仍以真实详情核验为准；**CLI 未返回上传完成前不算成功**，失败说明原因，不报残片为成功。
2. **新建目录**：只用已核验的既有父目录创建，不借自动建多层目录绕过范围校验；**同名由平台返回冲突**，此时请用户改名，或先 `cmcloud files list` 定位既有目录后改用其引用。
3. **下载**：本地目录必须由用户指定、已存在；**不做本地目录白名单判定**——是否可写由宿主／运行环境的文件系统权限决定，CLI 不额外限制本地目录，**Skill 不得在调用前自行拒绝用户指定的目录**；临时文件校验后再落最终文件；默认fail或用户指定rename时直接下载，不重复确认；同名覆盖先确认；批量逐项处理，一项失败不终止其他项。
4. **复制**：源与目标均使用当前账号的可信引用；**当前复制未提供重命名/覆盖/跳过/递归选项，冲突处理仅平台默认**；异步创建超时或结果未知时，先查回执/任务/目标目录，不自动切换执行方式、不重复创建副本。

确认卡结构与必展项见 [确认与安全边界](confirmation.md)。本领域追加：`cmcloud files upload` 本地文件大小；`cmcloud files mkdir` 同名会冲突、需提示用户改名；`cmcloud files copy` 冲突处理仅平台默认，不接受改名/覆盖/跳过；`cmcloud files download` 本地落点与磁盘占用、同名策略（默认fail，覆盖须用户确认）。

## 领域异常和恢复

| 异常 | 处理 |
| :-- | :-- |
| 上传已受理但完成校验或详情未核验 | `RUNNING`/`UNKNOWN`，不把会话或残片当成功 |
| 上传遇同名且策略为 `rename`/`dedupe` | 属**预期改名**：按实际名成功返回（`data.name`、`renamed=true`、`renamedFrom`），不报契约不一致、不重传、不说成失败 |
| 搜索仅有候选集、范围未核验，或满页且仍有游标（`complete=false`） | 返回已加载结果并标"未查全"，不说成"未找到"；本页未满或无游标即为取尽，不得再标"未查全" |
| 动态结果无已验证的文件映射 | 不执行文件详情补查；保留动态结果并说明详情不可得 |
| 创建目录发现同名对象 | 平台返回冲突；请用户改名，或先 `cmcloud files list` 定位既有目录后改用其引用 |
| 批量下载中某文件失败或源引用无效 | 该项失败且不进入下游，其他有效文件继续；输出逐项结果和本地路径，不暴露临时 URL |
| 批量复制部分成功或单个源引用无效 | 无效源不进入下游，其他有效源继续；返回 `PARTIAL` 与逐项结果，不把受理数当成功数 |
| 复制创建超时/任务缺失/结果未核验（含任务已结束但逐项结果不完整，批量复制可能不返回 `batchFileResults`） | 记 `UNKNOWN`，**不报成功、不写 0**，按 `references/protocol.md` 第 4 节 复核（用户追问时经 `operation.status`）；不重放 |
| 平台返回资源路径未在授权范围内（码 16110013） | CLI 已自动重查当前可操作专属目录，回执 `data.dedicatedRoot` 给出 `rootRef`/`namePath`；把当前可操作目录告知用户，**用户确认后重新发起**，重新发起的请求将使用该当前目录完成（落点仍只能是智能体专属目录及其子目录）；**不自动更改目标、不重试** |
| 目标越出允许范围、无合法祖先关系 | 执行前拒绝，不靠路径字符串前缀绕过 |

## 输出追加项

> 通用骨架见 [结果展示](output.md)；本节只列 files 域必须额外出现的信息。

- **上传**：结果句带 `→ <目标目录>`，括号内标 `<大小>`；`data.renamed=true` 时补一句"该目录已有同名文件，你的文件已改名为 `<data.name>`（原文件未改动）"，**以实际名回报，不谎称仍是原文件名**；`renamed=false` 时不提改名。
- **搜索 / 列表**：采用output.md的T2，属性只显示回执已有且本次需要的字段；无路径不拼造。**详情**直接回答用户所问字段，不强加列表汇总。
- **专属根上下文**：用户明确选择专属根时，展示路径只使用 `data.dedicatedRoot.namePath`，后续命令使用 `data.dedicatedRoot.rootRef`，不展示真实 ID。
- **新建目录**：结果句带 `→ <父目录>`；遇同名冲突时补一句"请改名，或改用已有目录"。
- **下载**：明细逐行 `- <名称> → <本地位置>`；失败项 `- <名称>：<失败原因>`。
- **复制**：受理中写"完成前不代表已生成"；完成后逐项给成功/失败与原因；**逐项结果不完整时按未知上报，不报成功**。

非覆盖下载以独占创建目标文件避免同名覆盖，成功过程不创建或删除临时硬链接。下载期间目标文件可见，只有完整性校验通过后才报告成功；失败时将未完成文件改名为同目录的 `.incomplete-<随机后缀>` 留证，不把残缺文件保留在请求的目标路径。显式选择覆盖时仍使用临时文件完成校验后替换原文件。
