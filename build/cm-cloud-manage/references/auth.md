# auth 授权与身份就绪

> 领域说明：仅在 `SKILL.md` 已把动作路由到 `auth`，或业务命令返回 `AUTH_REQUIRED` 后加载。执行前先取 `cmcloud help --topic auth --format json` 与 `cmcloud schema --command-id <command-id> --format json`。**参数类型、必填、枚举全集与上限一律以 CLI schema 为准**；本文件只给命令索引、参数名索引和编排规则，不内联 schema、凭据或成功码。

> `cmcloud auth status` 只回答"**这台机器上还有没有登录凭据**"——用于判断要不要重新登录；**它不回答"云盘授权了吗、授权完成了吗"**：授权与否只看取票命令（`cmcloud auth login`）的返回。

## 何时触发

> 以下为**触发线索**；本域命令只在用户**直接要求授权相关操作**，或业务命令返回 `AUTH_REQUIRED` 时调用。

- **业务命令返回 `AUTH_REQUIRED`（含用户未说过"登录"就直提文件操作）**：信封下发 `nextAction=auth.login` → **本轮调一次 `cmcloud auth login`**，把它回执里的短链/二维码展示给用户并结束本轮；`auth.login` 自身的回执不再下发该动作，**不得重复调用**。**不得反问"要不要先登录"，也不得跳过展示继续执行业务**。
- **登录/首次授权、切换账号 `cmcloud auth login`**：登录云盘、授权云盘、绑定我的云盘、连接移动云盘。
- **明确重新授权 `cmcloud auth reauthorize`**：重新授权、重新扫码授权。即使已授权也强制发起新会话；先生成一次确认计划。新会话确认后停用旧短票据，完成授权后通过普通取票恢复使用；不主动解绑。明确撤销旧授权或换账号仍走 revoke → logout，之后按需 login。
- **查询本地凭据 `cmcloud auth status`**：本地还登录着吗、这台机器上还有没有登录凭据、要不要重新登录、本机凭据是不是被清了。
- **确认授权完成 `cmcloud auth login`**（**仅当用户只问、不带业务动作时**）：我授权好了、扫完了、登录完了、授权完成了吗；用户说"继续刚才的"这类**带动作**的话，改为重走原业务命令。
- **退出账号 `cmcloud auth revoke` → `cmcloud auth logout`**：退出云盘、退出登录、清理本地登录状态、换个云盘账号、切换云盘账号、换绑另一个账号、解绑云盘、撤销授权、取消授权绑定。

## 何时不触发

- `帮助`、能力清单、`schema`、静态说明 → 不触发授权
- `先不授权了`、`停止等待`、`不登录了` → **没有对应命令**：只确认用户意图并停止当前任务，**不改动任何授权状态**，也不要说成"已取消授权"
- 需要用户扫码/登录的**唯一依据**是命令返回 `AUTH_REQUIRED`，不是模型自行判断
- 网络超时、签名或 IP 校验失败 → **不当作未授权**，不拉起授权页
- 已授权且业务就绪 → 不重复扫码
- 普通业务指令（查询、上传、分享等）→ **不预先调用** `cmcloud auth <action>`，授权检查交由业务命令在调用时完成

**授权入口与二维码展示口径**：

方式一直接使用本次 `auth.login` 返回的 `data.authPageUrl`，保持 SDK 原二维码入口地址，不提取 tid 拼接其他页面。二维码使用同一回执的 `qrImagePath` 或 `qrImageDataUri`，链接与二维码对应同一次会话。不要使用历史 tid、自行生成 tid 或改写授权路由。业务命令的 AUTH_REQUIRED 只用于触发一次 auth.login。

### 需要授权时的最终回复

这是正常AUTH_REQUIRED入口展示的唯一输出模板，优先于通用结果总结规则。**先由 Agent 依据当前真实运行环境自行判断运行形态**（当前是否在手机 App 内，不依据用户设备型号、网页标题或文件名猜测）：手机端用「手机端模板」，桌面端用「桌面端模板」；无法判断时按手机端处理（宁可不给二维码，也不承诺一张展示不出来的码）。**判断过程不得输出**：回复正文里不能出现“已获取授权入口”“当前为手机端运行环境”“按规则…”“正在按模板展示”这类过程性说明。只使用下列内容，替换真实链接；不要把模板再包进代码块或自定义卡片。

## 用户话术到结构化参数

> 本节说明各场景下**每个参数怎么选**；**参数类型、必填、上限、默认值与枚举全集以 `cmcloud schema` 为准**。

**明确重新授权 `cmcloud auth reauthorize`**

- 用户明确要求重新授权时使用；“授权了吗、我授权好了、要不要重新登录”不触发强制授权。明确撤销原绑定、退出或清除原授权后换账号仍走 revoke → logout。
- 不传执行参数时只冻结计划，不调用 SDK。向用户展示将发起新授权、需要重新完成授权；不能声称原权限已被撤销或本地凭据已清除。
- 取得一次明确确认后，调用 `<Python> <技能根>/scripts/cm_cloud_auth_api.py reauthorize --operationRef <ref> --planHash <hash> --format json`；profile 与计划一致。计划有效期5分钟；不要走 `operation confirm/execute/status`。
- CLI仅调用一次 `getToken(forcedAuth=True)`，不调用 revoke/logout；不继承普通取票的 scope 协商或清 uuid 自动重试。同一计划重复执行只读返回保存结果，中断、失败或结果未知均不重发强制请求，使用普通 auth login 核对。
- 新入口有效且 SDK 的新 uuid 已保存并回读匹配后才报告授权已发起，入口按原有模板展示并保存用于后续同会话重放；不在操作台账保存链接或二维码。
- 新会话确认后，强制请求使用当前 profile 登记的 scopeIds，不读取旧协商范围；在一次外层状态更新中保存 `reauthorizationPending` 业务标记并清除旧持久化 creditToken 和 scopeIds 缓存。后续普通取票从登记范围开始，仍允许按服务端明确回执重新协商。业务请求发现标记就跳过内存旧票据，普通取票失败也不退回旧票据。链接的30分钟重放期限不使业务标记过期；进程重启后仍保持待完成状态。SDK文件和外层状态没有跨文件原子事务，存储失败明确报错，不声称正常发起。
- 用户完成新授权后，有原任务直接继续业务：CLI先通过普通 getToken（forcedAuth 默认 false）承接保存的 uuid，取得并回读校验新票据成功后清除业务标记和待授权入口、刷新专属目录缓存，再使用新票据执行业务。只问授权状态时调用普通 auth login，同样可以完成承接。尚未授权时130088优先重放同一入口；失败或未完成不执行业务、不回退旧票据，不再次强制授权来确认。后台不轮询。
- SDK 自己对 uuid/accessToken 的保存和清除行为保持原包实现。普通 auth login 不强制授权，外层不开放 forcedAuth CLI 参数。

**登录/首次授权、切换账号 `cmcloud auth login`**

- `--profile`：要登录或切换的身份环境；多账号隔离时指定，缺省用当前 profile。
- 应用标识、权限范围与身份材料一律由 CLI 从受控配置取得——**Skill 不传，也不接受用户覆盖**。
- 返回 `AUTH_REQUIRED` 时拿到的是**授权入口**（短链、二维码、挑战引用），**不是授权结果**；此刻用户还没有授权。
- 返回 `SUCCESS` 表示**授权凭据已就绪**（`accessToken` 落在本机）；
- **措辞由用户意图决定，不由命令决定**——同一个返回，按用户怎么问换说法：

| 返回 | 用户问"授权了吗" | 用户说"我授权好了" |
| :-- | :-- | :-- |
| 已取到票据 | 已授权 | **授权完成，继续原任务** |
| 仍需授权 | 需要授权（按需展示入口） | **尚未完成**，请稍后再让我确认一次（**不说"你拒绝了"，也不说"已过期"**） |
| 环境／网络／配置类错误 | 环境或网络异常 | 环境或网络异常（**都不说成"未授权"**） |

**查询本地凭据 `cmcloud auth status`**

- `--profile`：待查询的身份环境；**不接受用户自报的账号、手机号或身份标识**当作可信身份。
- `--all`：`true` 时列出本机已登记的全部 skill（诊断用），**不与单 profile 语义混用**。
- **后端差异**：普通入口按 profile 的 `storage_backend` 分流——`file`（当前及缺省）读取本机加密状态文件、**不访问系统凭据库**；`keychain` 通过 keyring 访问系统凭据库。`--all true` 是**例外**，它是系统凭据库的全局诊断入口，不受单个 file profile 约束。
- **查到凭据 ≠ 凭据可用**：只说明"这台机器以前登录过"；票据是否有效、是否过期只能由取票命令体现，**不得据此对用户说"已授权可用"**。
- 用户问"授权了吗 / 授权完成了吗" → **不在此处回答**，走 `cmcloud auth login`。

**退出账号 `cmcloud auth revoke + cmcloud auth logout`**

> - 应用登记与身份材料（`devId`、`clientId`、`skillId`、`strategyId`、`clawUid`、`accessToken`）一律由 CLI 从受控配置与私有存储取得——**Skill 不传，也不接受用户覆盖**。
> - **顺序固定为（1）→（2）**：`revoke` 依赖本地 `accessToken`，先 `logout` 清掉本地凭据会让远端再也解不掉（返回 `AUTH_REQUIRED`）。只要清本地、不解远端时只用（2）。
> - **（2）是无条件兜底**：无论 `revoke` 成功、失败、被拒、超时还是结果未知，**都必须继续执行 `logout` 清掉本地凭据**（唯一例外是用户在确认后明确取消整个退出动作）。这是本域对 [执行流程](../SKILL.md)中断即停的**唯一例外**——本地不收拾干净，失效凭据会留在本机，导致下一次登录被服务端拒绝。
> - 退出账号后要换新账号，再走 `cmcloud auth login` 三段式：（1）解远端 →（2）清本地 → 登录新账号；**不把新账号的授权结果绑定到旧账号的任务**。

**（1）`cmcloud auth revoke`**

- `--profile`：要解绑的身份环境；**必须指向当前已登录的旧身份**，切换账号时**不得指向将要登录的新身份**。
- `--scope`：远端解绑的影响范围，**必填**；初期仅接受 `all`（该身份在当前设备与技能下的全部绑定），**不接受用户自报范围，也不得由模型放大或缩小**。
- 该命令**改变远端绑定**，按写流程走：先出影响计划与确认要求（`CONFIRMATION_REQUIRED`，`nextAction` 为 `operation.confirm`），**取得用户明确确认后才执行**；超时或中断属结果不确定（`UNKNOWN`），**不得自动重发**，只做一次幂等复核。
- **只解远端绑定，不等同本地退出：本地登录状态是否清理由（2）决定，不得把（1）执行完表述成"已退出登录"。**
- **失败不阻塞（2）**：返回 `AUTH_REQUIRED`（含「本地没有可用云盘授权凭据，未向服务端提交解绑请求」这一语义）或其它失败时，如实说明"远端绑定未解除"，**随即继续执行（2）清本地**；不因失败停下、不重试、不换成别的命令。该回执的 `nextAction` 为 `null`（本域不拉起授权），**不得因此调用 `cmcloud auth login`**。
- **执行阶段不走 `operation confirm`**：本域计划只认 `op_…` 引用且**不写入操作台账**；取得用户确认后，必须用**同一条命令**带 `--operationRef` + `--planHash` 执行：`cmcloud auth revoke --scope all --operationRef <op_…> --planHash <hash>`。信封里的 `nextAction=operation.confirm` 对本域只表示"待确认后执行"；**不得调用 `cmcloud operation confirm`**（它只处理台账里的 `cmop_…`，对本域引用会返回"引用未登记"）。

**（2）`cmcloud auth logout`**

- `--profile`：要退出的本地身份。
- 只清理本地会话的信息。
- 文件后端会清除授权信息与 SDK 身份副本，但保留本机该智能体/profile 的 `fallback_clawUid.json` 实例标识；重新授权会复用该标识，不会因退出生成新实例。
- **无条件执行**：作为退出账号流程的兜底步骤，（1）的任何结果都不改变本步骤必须执行；其结果只取决于本地清理能力，不依赖远端结果。
- 清理能力不可用时返回 `CAPABILITY_UNAVAILABLE`，**不得自行删除身份文件伪装成功**。
- 清理完成后，本机即可直接重新登录（`cmcloud auth login` 会给出授权入口），无需再手工清理。
- **执行阶段同样不走 `operation confirm`**：用 `cmcloud auth logout --operationRef <op_…> --planHash <hash>` 完成（`--operationRef` 与 `--planHash` 必须同时给出，取自计划回执）。

## 读流程

明确重新授权完成后可以直接继续原业务：CLI看到待完成标记会先普通取票，再使用新票据执行业务，无需用户再次登录；只问授权状态时用普通 auth login。

`cmcloud auth status` 可直接执行，**它只查本机凭据状态、不产生副作用**，可以自由重复调用。

**两条问题的分工**：用户问"授权了吗 / 我授权好了" → 走取票命令 `cmcloud auth login`；用户问"本地还登录着吗 / 要不要重新登录" → 走 `cmcloud auth status`。

**本地留痕 ≠ 可用**：本地凭据被撤销或过期后，留痕仍可能在，**不得把留痕当成授权或票据有效**。

**授权成功 ≠ 业务可用**：已授权不等于业务可用；就绪与否由业务命令的返回体现，此时**不重复拉起授权**。

## 确认点

1. **首次业务（不做授权预检查）**：业务命令返回 `AUTH_REQUIRED` 时，信封下发 `nextAction=auth.login` → 本轮调**一次** `auth.login`，展示其回执里的短链/二维码并**结束本轮** → 用户完成授权 → **用户再开口时按他说的做**：带业务动作就**直接重走那条业务命令**（CLI 内部取票即完成确认，不必先调 `cmcloud auth login`）；**只有单纯问"授权好了吗"才调 `cmcloud auth login` 确认** → 只读任务恢复；**写任务重新解析资源并生成计划，不能自动执行**。只有用户直接问状态、登录或退出时，才主动调用 `cmcloud auth <action>`。
2. **授权展示**：严格使用上文的宿主规则和简短模板；原任务保留在上下文，不添加额外卡片、任务清单或技术说明。用户完成授权后按原任务接续。
4. **账号切换**：先停止原账号下的任务恢复、失效原身份关联，再完成新账号授权；**不能把新账号的授权结果绑定到旧的操作**。用户说过放弃、或已切换账号、或授权已到期的，**迟到的授权结果不激活旧任务**。
5. **退出账号（`cmcloud auth revoke` → `cmcloud auth logout`）**：先出**退出账号确认卡**（见「输出追加项」）并**取得用户明确确认后才执行**；**执行阶段不走 `operation confirm`**——本域计划用 `op_…` 引用、不写入操作台账，确认后用**原命令**带 `--operationRef` + `--planHash` 执行（如 `cmcloud auth revoke --scope all --operationRef <op_…> --planHash <hash>`）；确认到手后内部按顺序执行两段——`revoke` 解远端 → `logout` 清本地，**顺序固定不可颠倒**，先清本地会导致远端再也解不掉。**无论 `revoke` 成功、失败还是结果未知，都要继续执行 `logout` 清本地**（唯一例外是用户取消整个动作）；`revoke` 结果不确定时按 `UNKNOWN` 复核、**不得自动重发**，并如实说明"远端绑定可能仍未解除，需在云盘 App 侧核对"；`logout` 只清本地，**不得把它描述为远端解绑**；两段都不删除宿主身份文件、不重置设备标识。

## 领域异常和恢复

### 临时票据缓存与自动恢复

CLI 将临时票据按智能体、profile、skill 隔离存储。file 模式复用 SDK 授权文件同目录的加密 `cmcloud_state.json`，不存明文、不修改长期授权凭据。临时票据的本地到期上限为获取后 29 分钟，提前 60 秒换票，正常可复用 28 分钟；服务端声明更短期限时取较短值。旧缓存也按原获取/保存时间应用此上限，不延长原到期时间；缺少时间信息则重新取票。

能开返回 HTTP 401，或业务码 `110044`（缓存失效）、`130090`（uid失效）、`16110038`（Token有效期不足）、`01000003`（令牌失效）、`103082`（权限已变更/授权回调处理失败）时，CLI 清理短票据缓存，调用 IDaaS SDK 重新取票，只重试当前失败请求一次；其中 `103082` 由业务下游直接返回时（该码不带 scopeIds），换票先按当前短票据调 IDaaS `validate` 查询服务端要求的 scopeIds 再取票（查不到按登记值取）；validate/desc 协商命中的 scopeIds 会**保存或更新**到本地，后续获取 creditToken 都用保存的 scopeIds。再次失败即停止并返回错误，不重做已成功的步骤，不由 Agent 重交整个计划。参数、签名、IP、应用登记及普通服务异常不触发自动换票；业务码 `401` 不等于 HTTP 401。只有 SDK 明确要求用户授权时才展示授权入口。

| 异常 | 处理 |
| :-- | :-- |
| 网络超时、签名失败、IP 校验失败 | **不能转换成未授权**；不自动要求扫码 |
| 授权页面已打开、已扫码、已跳转成功页 | **不能当作授权完成**；唯一依据是取票结果 |
| 用户拒绝授权或授权链接过期 | **当前无法区分**：两者都表现为"仍需授权"。只能报"尚未完成"，**不得谎称"你拒绝了"或"授权已过期"** |
| 上一轮授权未完成（本机留有待授权会话），再次取票 | CLI **保持同一次会话**并把同一个授权入口原样再给出来（信封照常带 `authPageUrl`/`challengeRef`）；`130088` 只表示"该会话尚未完成授权"，服务端此时不下发入口，因此 CLI 用本机缓存的入口重放。只有确实没有入口可重放（历史遗留会话、超出重放窗口、入口与当前 uuid 不同源）时才作废该会话并**重新下发授权入口**。Skill 按 `AUTH_REQUIRED` 展示回执里的入口即可，**不得**要求用户先退出登录，也**不得**说成"已拒绝""已过期""状态未知" |
| 平台侧授权权限已变更（`103082`） | CLI 先解析 desc 中服务端要求的 scopeIds 并**替换**取票入参后自动单次重试；desc 未携带 scopeIds 时，CLI 用当前短票据调用 IDaaS `validate` 接口换取服务端要求的 scopeIds 后再重试（重取仍走 SDK 原取票流程，后续业务请求自动改用新票据；拿不到 scopeIds 时保持原路径）。**协商命中的 scopeIds 保存/更新到本地，后续获取 creditToken 都用保存的 scopeIds**；重试后按新回执处理（多为 `103001` 需用户重新授权，属预期）。仍 `103082` 时按 `AUTH_REQUIRED` 话术说明"云盘授权权限已变更，需要重新完成授权"，**不得**当成普通网络错误或循环重试 |
| 业务下游直接返回 `103082`（授权回调处理失败，不带 scopeIds） | 与取票侧同义：CLI 视为票据类拒绝，清票后**先**用当前短票据调 IDaaS `validate` 换取服务端要求的 scopeIds，再以它为取票入参走 SDK 原有 preAuth 重新取票，并**用新票据重放当前业务请求一次**；validate 未给出 scopeIds 时按登记值取票；**协商命中的 scopeIds 保存/更新到本地，后续获取 creditToken 都用保存的 scopeIds**。重放仍失败则作废票据并按原失败语义返回（多为 `AUTH_REQUIRED` 需重新授权），**不得**循环重试 |
| 已授权但业务就绪未完成 | 提示继续完成就绪流程，不重复拉起授权 |
| 确认时仍未完成 | 如实报"尚未完成"，保留原任务上下文；**由用户稍后再问，不循环重试、不循环拉起授权** |
| 绑定关系不一致 | 提示核对绑定 / 重新授权 / 联系管理员；不自行重置 |
| 本机安全存储不可用 | 按当前后端区分：file检查目录可写性与加密文件读取；keychain检查系统凭据库。不得把存储错误当作未授权；不明文降级。详见protocol.md。 |
| 本机凭据文件读取状态 `corrupt`（文件存在但为空、编码/明文损坏、校验失败） | 说明"本地凭据文件已损坏（已留证备份为 `localCredentials.credentialFile.backupFile`）"，按需引导重新授权；**不得**说成"未登录/登录过期"，也不得声称凭据仍可用 |
| 读取状态 `fingerprint_mismatch`（机器标识变化或 SDK 指纹方案升级） | 说明"本地凭据与当前设备指纹不符，先前保存的凭据无法解密"，引导重新授权；与"登录过期"分开表述 |
| 读取状态 `version_unsupported` | 说明"本地凭据格式与当前 CLI 版本不兼容"，提示升级/重装；**不引导重新授权、不给重试建议** |
| 读取状态 `absent` | 按"需要授权"流程处理（本机确实没有可用凭据） |
| 读取状态 `legacy_plaintext` | 属迁移期历史明文格式，可正常使用；不提示异常，按后续迁移计划处理 |
| 迟到或过期的授权结果 | 不激活已取消或已切换的任务 |
| 用户要求解绑或撤销授权 | 走**退出账号**两段式，**确认后不调用 `cmcloud operation confirm`**（本域计划不入台账），而是用**原命令**带 `--operationRef` + `--planHash` 执行：先 `cmcloud auth revoke`（解远端，需用户明确确认）再 `cmcloud auth logout`（清本地）；**顺序固定 `revoke` → `logout`**（先清本地会让远端再也解不掉）；**无论 `revoke` 成功、失败还是结果未知，都必须继续 `logout` 清本地**（唯一例外是用户取消整个动作），并如实反馈"远端绑定未解除/未确认、本机已退出"；只要清本地时只用 `logout`；**解绑失败不得删除身份文件或本地凭据伪装成功** |

## 输出追加项

> 通用骨架见 [结果展示](output.md)；本节只列 auth 域必须额外出现的信息。

- **需要授权**：只输出上文简短模板，按宿主能力附二维码；没有图片能力时给可点击登录链接，并保留模板末尾的授权完成提示。
- **尚未完成**：`授权还未完成，稍后可以再让我确认一次`。
- **已授权**：说明“授权已生效”；有待办就继续原任务的下一安全步骤，不要求用户重述。单纯查询状态不追加业务探测。取票成功不证明业务可用，不主动输出凭据、路径或有效期。

**退出账号确认卡**（结构见 [确认与安全边界](confirmation.md)）：

```text
【待确认】退出云盘账号（<脱敏>）
· 对象：本机当前绑定
· 影响：云盘侧绑定将被解除（不可撤销），本地登录状态失效，未完成任务需重新开始
```
